## Batch 1: Foundations (`kb/dsa/foundations/`)

Each page uses the topic template (drafting brief section 4.1) and has front matter `priority: P1`, so it needs at least 8 `??? question` blocks. The Interview Angle questions are the theory questions that interviewers ask in coding rounds and in phone screens ("why is quicksort O(n²) in the worst case", "why is `HashMap` lookup O(1) on average"). Each page ends its Core Concepts or How It Works section with a short "Which patterns use this" list that links to the pattern pages.

### F1 — `01-complexity-analysis.md`, `02-arrays-strings-linked-lists.md`

`01`: Big-O, Big-Theta, Big-Omega with formal definitions and plain meaning; best, average, worst case; the common classes with an example each; how to analyze loops, nested loops, and recursion (recursion trees, the master theorem in its common form, with a source such as CLRS chapter 4); amortized analysis (aggregate method; dynamic array append as the worked example); space complexity including the call stack; a table from input limit `n` to the target complexity (about 10⁸ simple operations per second labeled as an approximate rule of thumb); how to state complexity in an interview.

`02`: arrays and memory layout (contiguous storage, cache lines, index arithmetic); dynamic arrays (`ArrayList` growth by about 1.5×, from the JDK source; amortized O(1) append); strings in Java (immutability, the string pool, `StringBuilder`, compact strings since JDK 9 — cite JEP 254; why `s += c` in a loop is O(n²)); `char` vs code points in brief; singly and doubly linked lists (operations and costs, sentinel nodes, runnable Java implementation with reverse and cycle detection links to pattern 03); arrays vs linked lists table.

### F2 — `03-stacks-queues-deques.md`, `04-hash-tables.md`

`03`: stack, queue, deque as abstract data types; array-based and linked implementations; circular buffer with runnable Java (head, tail, size, wrap-around, resize); `ArrayDeque` vs `Stack` vs `LinkedList` (from the javadoc: `Stack` is synchronized and extends `Vector`; `ArrayDeque` forbids `null`); priority queue in one line with a link to `06-heaps.md`; queue with two stacks (amortized O(1)); monotonic structures link to pattern 07.

`04`: hash functions (requirements, `hashCode` and `equals` contract from the `Object` javadoc); collision handling: separate chaining and open addressing (linear probing, quadratic probing, double hashing, deletion with tombstones); load factor and resize cost (amortized); Java `HashMap` facts from the JDK source and javadoc (default capacity 16, load factor 0.75, spreading of high bits, bins become trees at 8 entries when capacity is at least 64); worst case and hash flooding; `HashSet`, `LinkedHashMap`, `TreeMap` comparison; runnable Java open-addressing map. JDK internals beyond what DSA needs belong to `kb/java/04-collections-internals.md`.

### F3 — `05-trees-and-balanced-bsts.md`, `06-heaps.md`

`05`: tree terms (root, depth, height, degree, full, complete, perfect, balanced); binary tree traversals in one table with links to pattern 10; BST operations (search, insert, delete with the three delete cases) with runnable Java; why a BST degrades to O(n); AVL trees (balance factor, the four rotation cases at the concept level); red-black trees (the five properties, height at most 2·log₂(n+1) — cite CLRS chapter 13); `TreeMap` is a red-black tree (javadoc); B-trees and B+ trees in brief and why databases use them (link `kb/databases/03-indexing.md` as a backticked path).

`06`: binary heap as an array (parent and child index formulas); sift up and sift down with runnable Java min-heap; `heapify` in O(n) with the proof sketch (sum of heights); heap sort; `PriorityQueue` facts from the javadoc (min-heap by default, O(log n) `offer`/`poll`, O(n) `remove(Object)`, iteration order is not sorted); top-k and the k-way merge as uses, linking pattern 16; d-ary heaps and indexed heaps in brief (decrease-key for Dijkstra, link pattern 18).

### F4 — `07-graph-representations.md`, `08-sorting-algorithms.md`

`07`: graph terms (directed, undirected, weighted, DAG, connected components, degree, dense and sparse); adjacency list, adjacency matrix, edge list with memory and operation costs in a table; Java idioms (`List<List<Integer>>`, `List<int[]>[]`, `Map<Integer, List<Integer>>`); building a graph from LeetCode inputs (edge arrays, prerequisites); implicit graphs (grids, word ladders, state spaces) with the 4-direction and 8-direction arrays; which representation each algorithm prefers, linking patterns 11, 12, 13, 18, and 24.

`08`: insertion, selection, bubble, merge, quick (Lomuto and Hoare partition, random pivot, three-way partition), heap, counting, radix, bucket sort — each with runnable Java or a compiling method, time and space in all cases, and stability; a comparison table; the Ω(n log n) lower bound for comparison sorts with the decision-tree argument; what `Arrays.sort` uses: Dual-Pivot Quicksort for primitive arrays and TimSort (stable) for object arrays, from the javadoc; `Collections.sort` and `List.sort`; comparators and the overflow bug in `a - b`; quickselect for the k-th element with a link to pattern 16.
