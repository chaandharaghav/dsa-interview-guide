# Phase 1: LLD — Implementation Plan

**Goal:** Write the complete `kb/lld/` subject: the interview procedure, the machine-coding guide, 11 fundamentals pages, 24 case studies with runnable `Main.java`, a cheatsheet, and a practice file.

**Spec:** `docs/superpowers/specs/2026-10-14-software-engineering-kb-design.md` (sections 3.2, 4, 5.1, 5.2, 6, 7, 8, 9)

**Process (spec section 9):** Sonnet subagents draft. Each subagent prompt tells the subagent to read `docs/superpowers/drafting-brief.md` in full first, then gives one assignment from this plan. Opus reviews every draft against the spec section 8.5 checklist, fixes it or sends it back, runs `tools/check-all.sh`, and commits each batch.

Ruling: the prompt tells the subagent to read the brief file instead of pasting its text. The file is the same text, and a read keeps the brief identical for all subagents. Cost if wrong: a subagent skips the brief; the review catches the result.

## Common assignment text

Every assignment includes this paragraph:

> Read `docs/superpowers/drafting-brief.md` in full before you start. It is binding. Then read `kb/lld/README.md` for the subject's page list. Write in Java 21. Each pattern or principle gets a short realistic example (an order system, a payment flow, a document editor) instead of `Foo` and `Bar`. Where a concept has a wrong form and a right form, show both in compilable Java, with the problem the wrong form causes.

## Batch 1: Fundamentals (`kb/lld/fundamentals/`)

### A1 — `01-oop.md` (P1), `02-solid.md` (P1)

`01-oop.md` must cover:
- Class and object; state and behavior; identity and equality (link the `equals`/`hashCode` contract to `java/01` in plain text, because that page does not exist yet).
- Encapsulation: private state, invariants, defensive copies, why getters and setters for every field break encapsulation.
- Abstraction: interface as a contract; hiding the implementation.
- Inheritance: `extends`, method overriding rules (covariant returns, access, exceptions), `super`, constructor chaining, the fragile base class problem.
- Polymorphism: compile-time (overloading) and runtime (overriding, dynamic dispatch). Overload resolution traps (boxing, varargs, `null` argument).
- Interfaces and abstract classes in Java 21: default, static, and private interface methods; when to use each; the diamond problem with default methods and how Java resolves it.
- Composition and inheritance: "has-a" and "is-a", delegation, why "favor composition" holds, when inheritance is the right choice.
- Access modifiers, `final` classes and methods, `static` members, nested and inner classes in design terms.
- Records, sealed classes and interfaces as modeling tools (Java 17+).
- Interview questions to include: the four pillars with examples; abstract class vs interface; overloading vs overriding; can you override a static or private method; composition vs inheritance with an example; why `String` is final; what breaks if a subclass overrides `equals` but not `hashCode`.

`02-solid.md` must cover each of S, O, L, I, D with: the definition (Robert C. Martin's wording, sourced), a Java violation, the problem it causes, the refactored Java, and how to spot the violation in an interview design. LSP must include the rectangle/square example and the preconditions/postconditions rules. DIP must separate dependency inversion from dependency injection. Also cover: how SOLID principles conflict with YAGNI and KISS, and when over-applying SOLID makes a design worse.

### A2 — `03-design-principles.md` (P2), `11-anti-patterns.md` (P2)

`03-design-principles.md`: DRY (and the "wrong abstraction" risk), KISS, YAGNI, Law of Demeter (with a chained-call example and the fix), cohesion types and coupling types (with examples), tell-don't-ask, immutability (how to make a class immutable in Java; benefits for thread safety), principle of least astonishment, separation of concerns, program to an interface, fail fast.

`11-anti-patterns.md`: God object, anemic domain model, overuse of inheritance (deep hierarchies), Singleton overuse (hidden global state, test pain), primitive obsession, feature envy, shotgun surgery, circular dependencies, magic numbers and strings, boolean parameters, leaky abstractions, premature optimization, copy-paste programming, service locator. Each: the symptom, a Java example, the fix. Link to `engineering-practice/02` (code smells) in plain text.

### A3 — `04-uml-class-and-sequence-diagrams.md` (P1), `05-domain-modeling.md` (P1)

`04-uml...`: class diagram notation in Mermaid (`classDiagram`): visibility markers, attributes, methods, abstract and interface stereotypes; relationships: association (with multiplicity), aggregation, composition, dependency, inheritance, realization — each with the Mermaid syntax, the meaning, and the Java code that it maps to. Sequence diagrams in Mermaid (`sequenceDiagram`): participants, sync and async messages, return messages, `alt`/`loop`/`opt` blocks. State diagrams (`stateDiagram-v2`) for an order lifecycle. What level of UML detail an interviewer expects in a 45-minute round. Common notation errors (aggregation vs composition confusion).

`05-domain-modeling.md`: noun-verb analysis of a problem statement (worked on a full example statement); entities vs value objects; aggregates and aggregate roots (DDD terms, defined); enums vs class hierarchies (when a type needs behavior); modeling state with an enum plus a state machine; identifying responsibilities (CRC cards); where business rules live; IDs and equality; modeling money, time, and quantities correctly (`BigDecimal`, `java.time`, no `double` for money). Worked example: from a library-system statement to a class diagram.

### A4 — `06-creational-patterns.md` (P1)

Singleton (eager, lazy with `synchronized`, double-checked locking with `volatile` and why `volatile` is needed, holder idiom, enum Singleton; reflection and serialization attacks and defenses; why Singleton hurts testing), Factory Method, Simple Factory (and why it is not a GoF pattern), Abstract Factory, Builder (telescoping constructor problem; a Builder with validation; Lombok-free), Prototype (shallow and deep copy, `Cloneable` problems, copy constructors), Object Pool in brief, Dependency Injection as an alternative to factories. For each pattern: intent, the problem, structure (Mermaid class diagram), Java code, when to use, when not to use, JDK examples (for example `Calendar.getInstance`, `StringBuilder`, `DocumentBuilderFactory`, `List.of`), interview questions.

### A5 — `07-structural-patterns.md` (P1)

Adapter (object and class adapter), Bridge, Composite, Decorator (with Java I/O streams as the JDK example; Decorator vs inheritance explosion), Facade, Flyweight (with `Integer.valueOf` cache as a JDK example), Proxy (virtual, protection, remote, caching; JDK dynamic proxies with `java.lang.reflect.Proxy`, runnable). For each: intent, problem, Mermaid structure, Java code, when to use and not, JDK or framework examples, the patterns it is confused with (Adapter vs Facade vs Decorator vs Proxy table), interview questions.

### A6 — `08-behavioral-patterns.md` (P1)

Chain of Responsibility, Command (with undo), Iterator (and Java `Iterator`/`Iterable`), Mediator, Memento, Observer (and why `java.util.Observer` is deprecated; listener lists; memory leaks from listeners), State, Strategy (with lambdas), Template Method, Visitor (double dispatch; sealed interfaces plus pattern matching as a modern alternative), Interpreter in brief, Null Object. For each: intent, problem, Mermaid structure, Java code, when to use and not, JDK examples. Include a comparison table: Strategy vs State vs Template Method; Observer vs Mediator; Command vs Strategy. Interview questions at P1 depth.

### A7 — `09-concurrency-in-lld.md` (P1), `10-architectural-patterns.md` (P1)

`09-concurrency-in-lld.md`: where races appear in LLD problems (seat booking, parking spot assignment, inventory decrement, wallet balance, rate limiter counters); critical sections; `synchronized` vs `ReentrantLock` vs atomics vs concurrent collections for each case; lock granularity (global lock vs per-object lock vs striped locks); deadlock in designs and lock ordering; optimistic locking with version numbers (and its database equivalent, plain-text link to `databases/04`); immutable objects for thread safety; producer-consumer with `BlockingQueue`; thread-safe Singleton (link to 06); how to discuss concurrency in an interview without over-engineering. Each case with runnable Java and deterministic output. Primitive details link to `java/07` and `java/08` in plain text (home pages, not written yet).

`10-architectural-patterns.md`: layered architecture (controller-service-repository), MVC, hexagonal (ports and adapters), clean architecture and the dependency rule, repository pattern, DTO and mapping, dependency injection (constructor injection, why not field injection), service layer, unit of work in brief. How to lay out packages in a machine-coding round. CQRS and event sourcing: one paragraph each plus a plain-text link to `hld/fundamentals/16` (home page).

## Batch 2: Procedure pages (`kb/lld/`)

### B1 — `how-to-approach-lld.md` (P1), `machine-coding-round.md` (P1)
